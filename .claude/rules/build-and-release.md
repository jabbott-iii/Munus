# Build, CI/CD, dependencies and licenses

Change CI, CD, Docker or release configuration only when the task requires it, and call out every
such change in the completion report. CI behaviour is proven only by a GitHub run; say so.

## Toolchain

- cgo is required everywhere (`mattn/go-sqlite3`). Never set `CGO_ENABLED=0` for a build that
  includes the database.
- `go.mod` holds the minimum version (`go 1.26.0`). CI, CD and govulncheck use the latest patch
  (`go-version: "1.26.x"`, `check-latest: true`). A Go minor upgrade is deliberate (Dependabot
  ignores it): use `/dependency-update go`.
- golangci-lint `v2.13.2` is named in `ci.yml`, the `Makefile` (help and skip message), README,
  `CONTRIBUTING.md` and the PR template. Change all of them together.
- `make check` mirrors CI's vet, lint and test steps and adds `fmt-check` and `race`, which CI does
  not run. CI's `go mod tidy` drift check has no make target. Keep `Makefile` and `ci.yml` in step.

## Workflows

- Every action is pinned to a full commit SHA with a `# vX.Y.Z` comment. Downloads are pinned by
  version and verified by SHA-256 (llvm-mingw in `cd.yml`: bump `LLVM_MINGW_VERSION` and
  `LLVM_MINGW_SHA256` together).
- Least privilege: top-level `permissions: contents: read`. In `cd.yml` only the tag-only
  `release` job has `contents: write` (no OIDC); attestation jobs have `id-token: write` and
  `attestations: write` only; the `image` job has `packages: write` only, no checkout and no build.
  Release checkouts do not persist credentials. Do not widen any of this or add
  `pull_request_target`.
- Release tags must match `^v[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.-]+)?$` (checked in `cd.yml`
  before any release is created; `+` build metadata is rejected even though the `Makefile`'s
  `check-version` accepts it). Version strings passed to builds match `^[0-9A-Za-z._+-]+$`.
  Image tags drop the `v`; only stable releases move `X.Y` and `latest`.
- In steps with `shell: bash` (which adds `pipefail`), smoke tests use
  `munus … | grep pattern > /dev/null`, not `grep -q`, which can make munus fail with SIGPIPE.
- `security.yml`: CodeQL (`security-extended`) and gosec (`-no-fail`, SARIF upload) report to Code
  Scanning; govulncheck fails the job when a known vulnerability is reachable. Do not remove or
  weaken a scan. The only secrets used are `CODECOV_TOKEN` and `GITHUB_TOKEN`; never echo them.
- Dependabot pull requests get the same review and checks as any other; they are never merged
  automatically.

## Dockerfile

- Stages: `source` → `builder` (image binary) and `static-builder` → `static` (Linux release
  binary, built only when targeted) → runtime image.
- Builder `golang:1.26-alpineX.Y` and runtime `alpine:X.Y` stay on the same Alpine release;
  `apk` packages are pinned (`build-base`, `ca-certificates`, `tzdata`). Alpine repositories keep
  only the newest revision, so a pin breaks the build when upstream moves; follow
  `/dependency-update docker`.
- The `static` build tags must equal `linuxReleaseTags` in `tools/licenses/main.go`. Both builds
  link with `-Wl,-z,stack-size=8388608` (musl's default 128 KiB thread stack; `docker.yml` checks
  it) and stamp `main.version` from the `VERSION` build argument.
- The image runs as UID 10001 with `HOME=/app/data` and `MUNUS_DB_PATH=/app/data/munus.db`, and
  ships `LICENSE`, `NOTICE` and `THIRD_PARTY_LICENSES` in `/usr/share/licenses/munus/`. Keep all
  of that, and README "Docker", in step.
- The smoke-test images `debian:11` and `alpine:X.Y` in `cd.yml` and `docker.yml` are not tracked
  by Dependabot; move them with the Alpine release.

## Licenses

- `THIRD_PARTY_LICENSES` is generated by `make licenses` (`go run ./tools/licenses`). Never edit it
  by hand. It lists no versions, so it changes only when a module is added or removed or a license
  text changes.
- The `NOTICE` module list is maintained by hand and checked by `go test ./tools/licenses`: add or
  remove lines in the existing format (module path, copyright holder, license) under the right
  heading. Do not change the copyright line.
- A module without a license file needs a reviewed entry in `readmeLicenses` (currently
  `mattn/go-localereader`).
- `tools/licenses/musl-COPYRIGHT`, `muslVersion` and `muslAlpineRelease` follow the Dockerfile's
  Alpine release; the test fails until they agree.
